# 속삭임 감지 음성 변환 시스템 — 프로젝트 컨텍스트 정리

> 최종 업데이트: 2025년 3월 24일

---

## 1. 프로젝트 목표

속삭임 음성으로 LLM(Claude API)과 소통할 수 있는 애플리케이션 개발. 일상생활 소음 환경(카페, 지하철 등)에서도 속삭임을 정확히 인식하는 STT 파이프라인 구축이 핵심 과제.

전체 흐름은 속삭임 음성 입력 → 노이즈 제거 → Whisper large-v3 STT → Claude API → 텍스트 출력 또는 ElevenLabs TTS로 구성된다.

---

## 2. 아키텍처 결정사항

**STT 방식은 서버 기반 API를 채택했다.** Whisper는 Python 기반으로 모바일 온디바이스 내장이 비현실적이기 때문에, 모바일 앱에서 오디오를 캡처한 뒤 서버로 전송하고 결과를 수신하는 구조를 취한다.

**STT 모델 전략은 2단계로 나뉜다.** 1단계에서는 Whisper large-v3을 그대로 사용하며 성능을 검증하고, 성능이 부족할 경우 2단계에서 파인튜닝을 고려한다. 파인튜닝 모델을 위한 자리는 설계에 이미 포함되어 있다.

**API 후보로는 Groq API가 유력하다.** Whisper large-v3을 제공하면서 LPU 칩 기반으로 속도 우위가 있다. OpenAI Whisper API와 자체 서버 운영도 대안이다. 다만 Groq의 large-v3-turbo와 원본 large-v3의 속삭임 인식 성능 차이는 아직 미검증 상태로, 비교 대상에 포함해야 한다.

**모바일 앱은 iOS(Swift)와 Android(Kotlin)로 각각 네이티브 개발하며,** 공통 백엔드 STT 모듈을 래핑하여 사용한다.

---

## 3. 현재까지 실험 결과

### 실험 환경

한국어 ASMR 유튜브 영상 세그먼트 76개를 데이터로 사용하고, 지하철 소음을 합성하여 테스트했다. 정답(REF)은 유튜브 자막 기반인데, ㅋㅋ, 이모지, 괄호 설명 등이 포함되어 있어 실제 인식률은 수치보다 높을 것으로 추정된다.

현재 파이프라인은 noisereduce(stationary=False, prop_decrease=0.8) → Whisper large(MPS, fp16=False, language=ko)로 구성되어 있다.

### 결과

| 조건 | CER | WER |
|------|-----|-----|
| Clean ASMR | 24.7% | 39.3% |
| 소음 합성 SNR -10 | 40.7% | 57.1% |

### 핵심 관찰

- **CER < WER 격차가 큼**: 단어 일부만 틀리는 패턴으로, LLM이 문맥으로 복원 가능한 수준이다.
- **Clean 기준 CER 30% 이하 샘플이 절반 이상**: 파인튜닝 없이도 LLM 입력으로 활용 가능성이 있다.
- **SNR -10에서 환각 발생**: 외국어나 전혀 다른 텍스트가 출력됨. confidence 기반 필터링이 필요하다.
- **REF 노이즈**: 자막 기반 정답의 한계로 실제 성능은 수치보다 높을 것으로 추정.

## 4. 핵심 문제 인식: 속삭임의 SNR 특성

일반 음성은 60~70dB SPL이지만 속삭임은 30~40dB SPL로 20~30dB 낮다. 따라서 흔히 인용되는 환경별 SNR 수치(카페 +5~+15, 지하철 0~+5)는 일반 음성 기준이며, 속삭임에는 적용되지 않는다.

**속삭임 기준으로 보면 지하철에서 SNR -10 수준은 극한 조건이 아니라 실제 타겟 조건이다.** 이는 현재 SNR -10 실험 결과(CER 40.7%, 환각 발생)가 곧 실전 성능임을 의미하며, 문제의 난이도가 당초 예상보다 높다는 것을 뜻한다.

다만 마이크-입 거리라는 변수가 있다. 블루투스 이어폰 마이크가 입에서 수 cm 거리에 있으면 근접 효과로 SNR이 개선될 수 있고, 반대로 스마트폰 마이크라면 SNR -10 이하도 충분히 가능하다. **현재 하드웨어 팀의 프로토타입이 미완성이라 실제 입력 데이터의 특성은 확정할 수 없는 상태다.**

## 5. 다음 단계 계획

하드웨어 프로토타입이 나오기 전까지는 소프트웨어 쪽에서 가능한 실험을 병렬로 진행한다.

### Track A: SNR 구간별 베이스라인 측정

현재 SNR -10 단일 조건만 테스트한 상태이므로, SNR +15 / +5 / 0 / -5 / -10 구간별로 Whisper의 베이스라인 성능을 측정한다. 높은 SNR이 기본이라는 전제 없이, 모든 구간을 실전 시나리오로 동등하게 다룬다.

CER, WER 외에 Whisper의 no_speech_prob과 세그먼트별 avg_logprob도 함께 수집한다. 이 두 지표를 조합하면 노이즈 제거 모델 도입 전에도 환각을 걸러내는 confidence 기반 필터링에 활용할 수 있다.

### Track B: 딥러닝 노이즈 제거 모델 비교

동일한 SNR 구간에 대해 여러 노이즈 제거 모델을 적용한 후 Whisper 성능을 비교한다. 후보 모델은 다음과 같다.

- **DeepFilterNet**: 경량, 실시간 처리 가능
- **Meta Denoiser**: Meta 연구진 개발
- **Resemble Enhance**: 음성 품질 향상 특화
- **noisereduce (현재 사용 중)**: 전통적 스펙트럼 감산 기반, 베이스라인 역할

### 분석 방법

Track A와 B의 결과를 겹쳐서 "SNR 구간 × 노이즈 제거 모델 → CER/WER 매트릭스"를 만든다. 이를 통해 어떤 SNR 구간에서 어떤 모델이 얼마나 개선을 주는지 한눈에 파악한다.

### 이후 단계 (실험 결과에 따라 결정)

1. 딥러닝 노이즈 제거로도 성능 부족 시 → Whisper 파인튜닝 검토
2. 하드웨어 프로토타입 도착 시 → 실제 디바이스 데이터로 전체 파이프라인 재검증
3. 성능 검증 완료 후 → 모바일 앱 개발 및 API 서버 구축

---

## 6. 미결 사항

- **하드웨어 프로토타입 미완성**: 실제 입력 데이터의 SNR 특성을 모르는 상태. 마이크 종류와 위치에 따라 결과가 크게 달라질 수 있다.
- **Groq large-v3 vs large-v3-turbo**: 속삭임 저에너지 음성에서의 성능 차이 미검증.
- **파인튜닝 여부**: Track A/B 실험 결과에 따라 결정 예정.
- **Confidence 필터링 임계값**: no_speech_prob + avg_logprob 조합의 최적 threshold를 실험에서 탐색해야 한다.
